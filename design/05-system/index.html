Halyard

One component stylesheet, four themes, four products. Halyard is the system behind a paper map sheet, a dark control tower, a warm phone app and a black terminal — which is the hardest case a system can be put to: the same button has to be right on cream, on near-black, in a 44-pixel row, and in a monospaced grid.

01

Overview

Three layers, one direction: primitives → semantic tokens → components. Components never name a colour, a font family or a duration; they read a semantic token. A theme is a block of semantic assignments and nothing else.

Layer 1 · primitives--p-*

A ramp of ink, paper, moss, ochre, clay, sky. Named for what they are, never used by a component.

18 primitives
Layer 2 · semantic--surface, --ink, --accent…

Twenty roles that say what a colour is for: surface, ink, ink-2, ink-3, line, accent, ok, warn, danger, info, data-1…4, focus, shadow-1…3, grid-ink.

20 roles per theme
Layer 3 · components.btn, .inp, .tbl…

Twenty-four components, one stylesheet, no colour literal below the theme blocks. Switching the theme re-skins the whole kit in one attribute.

grep: 0 hex in the kit
What the themes are allowed to change
  • every colour role, including the three shadows and the grid ink
  • the three type roles (display, text, mono) and the modular ratio
  • the radius scale — 0 px in a terminal, 26 px in a phone app
  • one density multiplier (--pad)
  • color-scheme, so form controls and scrollbars agree
A theme may not add a component, a class, or a colour a component has to override.
The contract a theme must satisfy
  • ink on surface ≥ 7:1, ink-3 on surface ≥ 4.5:1
  • accent-ink on accent ≥ 4.5:1 (the button's label)
  • every status colour legible on its own soft background
  • data-1…4 separable in a 24 px swatch and by luminance, not only by hue
  • the four status colours must not collapse into each other at 11 px
Checked live in the Colour section; the numbers are measured, not declared.

09

Using a theme

What a product does to adopt Halyard, and what it must not do.

Adopt it
<html data-theme="deck">          <!-- one attribute -->
<link rel="stylesheet" href="system.css">

<button class="btn">Export</button>
<button class="btn ghost sm">Cancel</button>
<span class="pill warn">queued</span>
<input class="inp" aria-invalid="true"
       aria-describedby="email-err">
A product adds classes only for its own domain (a map sheet, a bird row, a log line), never for colour.
Do not
  • Set a colour in a product stylesheet. If a role is missing, the theme is incomplete — fix the theme.
  • Add a component class that overrides a radius, a shadow or a font family.
  • Use data-2 for "warning" because it looked nice in one chart.
  • Ship a theme that passes contrast on surfaces but not on the soft status backgrounds.
  • Introduce a duration. There are four.
